
=== command help

>>> [CLI] air run --help
Submit a workload to Databricks serverless GPU compute.

The workload is described by a YAML file (see --file). To look up a YAML
field, pass its path to -h as a separate argument:

  databricks air run -h config                            all fields
  databricks air run -h config.compute                    one section
  databricks air run -h config.compute.accelerator_type   one field

To have a coding agent write the YAML and follow the run, install the
databricks-ai-runtime skill:

  databricks aitools install --skills-only --skills databricks-ai-runtime

Usage:
  databricks air run [flags]

Examples:
  # Submit and stream logs until the run finishes
  databricks air run -f workload.yaml --watch

  # Validate the config against the workspace without submitting
  databricks air run -f workload.yaml --dry-run

  # Try a different GPU without editing the file
  databricks air run -f workload.yaml --override compute.accelerator_type=GPU_1xH100

Flags:
  -f, --file string              Path to the workload YAML config
      --watch                    Stream logs until the run completes
      --override stringArray     Override a YAML field, e.g. compute.num_accelerators=8 (repeatable)
      --dry-run                  Validate the config against the workspace without submitting a run
      --idempotency-key string   Return the existing run if this key was already used
  -h, --help                     help for run

Global Flags:
      --debug            enable debug logging
  -o, --output type      output type: text or json (default text)
  -p, --profile string   ~/.databrickscfg profile
  -t, --target string    bundle target to use (if applicable)

=== schema overview

>>> [CLI] air run -h config
config
  Workload YAML schema. For details on a field, pass its path to -h, for example:

    databricks air run -h config.compute.accelerator_type

  Minimal example:
    experiment_name: my-run
    compute:
      num_accelerators: 1
      accelerator_type: GPU_1xA10
    code_source:
      root_path: .
    command: python "$CODE_SOURCE_PATH/train.py"

  Workload:
    experiment_name              (required) Name of the experiment.
    compute                      (required) Which accelerators to run on and how many.
    command                      (required unless containers is set) Shell command that starts the workload.
    environment                  Python dependencies, runtime version, or a Unity Catalog image for a single-command run.
    containers                   Rank-partitioned containers for heterogeneous workloads.
    env_variables                Plain environment variables, as NAME: value.
    secrets                      Environment variables sourced from secrets, as NAME: scope/key.
    code_source                  Local code to upload and make available to the run.
    parameters                   Free-form values passed through to the workload.

  Execution:
    max_retries                  How many times to retry a failed run.
    timeout_minutes              Wall-clock limit for the run in minutes.
    idempotency_token            Reuse token: a repeat submission with the same token returns the existing run instead of starting another.

  MLflow tracking:
    mlflow_run_name              Name for the MLflow run.
    mlflow_experiment_directory  Workspace directory holding the MLflow experiment.
    mlflow_artifact_location     DBFS location where MLflow artifacts are written.

  Access and cost attribution:
    permissions                  Who may view or manage the run, as a list of principal plus level grants.
    usage_policy_name            Usage policy to attribute the run's usage to, by name.
    usage_policy_id              Usage policy to attribute the run's usage to, by id.

For details on a field, run "databricks air run -h config.<field>".

Let a coding agent write this YAML for you with the databricks-ai-runtime skill:
  databricks aitools install --skills-only --skills databricks-ai-runtime
  (add --scope project to install into the current project)
  https://github.com/databricks/databricks-agent-skills/tree/main/skills/databricks-ai-runtime

=== nested object lists its fields

>>> [CLI] air run -h config.compute
config.compute
  Which accelerators to run on and how many.

  Supported accelerator types:
    GPU_1xH100 - 1 accelerator per node
    GPU_8xH100 - 8 accelerators per node
    GPU_1xRTX6000 - 1 accelerator per node

  Fields:
    num_accelerators  (required) Total number of GPUs to allocate.
    accelerator_type  (required) Which accelerator to run on, e.g. GPU_1xA10.

  Provisioned capacity (optional):
    pool_id           GPU pool to run on, by id.
    priority_class    Scheduling priority within the pool: BEST_EFFORT (lowest, preemptable) or NORMAL.

For details on a field, run "databricks air run -h config.compute.<field>".

>>> [CLI] air run -h config.compute.pool_id
config.compute.pool_id
  GPU pool to run on, by id. A GPU pool is a pre-provisioned accelerator reservation; contact your Databricks account team to provision one. Must be 1-255 characters. List available pools with 'databricks air pools list'.

  Type:     string
  Required: no

  Type:     string
  Required: no

>>> [CLI] air run -h config.environment.version
config.environment.version
  Managed environment to start from, e.g. 6 for the Standard environment or databricks_ai_v6 for the Databricks AI environment (default: 6). Standard includes CUDA but, from version 5, not PyTorch; add it with dependencies. The Databricks AI environment adds PyTorch, Transformers, and other ML libraries. See Docs below for supported versions and package lists.

  Docs:
    AWS:   https://docs.databricks.com/aws/en/machine-learning/ai-runtime/develop-workloads/environment
    Azure: https://learn.microsoft.com/azure/databricks/machine-learning/ai-runtime/develop-workloads/environment

  Type:     string or int
  Required: no

=== code source fields

>>> [CLI] air run -h config.code_source
config.code_source
  Local code to upload and make available to the run.

  Fields:
    root_path      (required when code_source is set) Root of the code source to archive.
    remote_volume  Volume to upload the archive to.
    git            Pin the snapshot to a specific git revision.
    include_paths  Restrict the archive to these paths, relative to root_path and without "..".

For details on a field, run "databricks air run -h config.code_source.<field>".

=== union field

>>> [CLI] air run -h config.code_source.git.remote
config.code_source.git.remote
  No longer supported: the snapshot archives your local copy. Only false is accepted; use commit to pin a revision.

  Type:     bool or string
  Required: no

=== git-pinned subdirectory documents root_path scoping

>>> [CLI] air run -h config.code_source.root_path
config.code_source.root_path
  Root of the code source to archive. A git-pinned subdirectory packages only that subtree.

  Type:     string
  Required: when code_source is set

=== free-form map keys are not schema fields

>>> [CLI] air run -h config.parameters.learning_rate
Error: "config.parameters" holds user-defined keys, so "learning_rate" is not part of the schema; see "config.parameters" instead
