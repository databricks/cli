>>> print_requests.py //permissions
{
  "method": "PUT",
  "path": "/api/2.0/permissions/pipelines/[OLD_PIPELINE_ID]",
  "body": {
    "access_control_list": [
      {
        "group_name": "users",
        "permission_level": "CAN_VIEW"
      },
      {
        "permission_level": "IS_OWNER",
        "service_principal_name": "[USERNAME]"
      }
    ]
  }
}

>>> read_state.py pipelines foo.permissions id
pipelines foo.permissions id='/pipelines/[OLD_PIPELINE_ID]'

=== Switch from catalog to storage: the pipeline is recreated with a new ID
>>> update_file.py databricks.yml catalog: main storage: dbfs:/my-storage

>>> update_file.py databricks.yml target: ${resources.schemas.bar.name} #target: ${resources.schemas.bar.name}

>>> [CLI] bundle plan --output json
{
  "object_id": {
    "action": "update_id",
    "reason": "id_changes",
    "old": "/pipelines/[OLD_PIPELINE_ID]",
    "new": "",
    "remote": "/pipelines/[OLD_PIPELINE_ID]"
  }
}

Streaming Tables (STs) and Materialized Views (MVs) managed by them. Recreating the pipelines will
restore the defined STs and MVs through full refresh. Note that recreation is necessary when pipeline
properties such as the 'catalog' or 'storage' are changed:
