
=== Deploy a volume

>>> [CLI] bundle deploy
Uploading bundle files to /Workspace/Users/[USERNAME]/.bundle/test-bundle-[UNIQUE_NAME]/default/files...
Created volumes.volume1
Files: 3 uploaded, 0 deleted
Resources: 1 created, 0 changed, 0 deleted, 0 unchanged

=== Out of band, rename the volume away, and create another one under its name

>>> [CLI] volumes update main.test-schema-[UNIQUE_NAME].myvolume --new-name myvolume-moved
{
  "full_name": "main.test-schema-[UNIQUE_NAME].myvolume-moved",
  "volume_id": "[VOLUME_ID]"
}

=== The other volume has another volume_id, so the plan does not take it for the bundle's: it plans a create

>>> [CLI] bundle plan
Warn: planning resources.volumes.volume1: id="main.test-schema-[UNIQUE_NAME].myvolume" holds another object: its volume_id is "[FOREIGN_VOLUME_ID]", not "[VOLUME_ID]" as recorded, so it is not treated as this bundle's. To manage it with this bundle, run 'bundle deployment unbind' and 'bundle deployment bind'.
create volumes.volume1

Plan: 1 to add, 0 to change, 0 to delete, 0 unchanged

To manage it with this bundle, run 'bundle deployment unbind' and 'bundle deployment bind'.

  delete resources.volumes.volume1

This action will result in the deletion of the following volumes.

is removed from the catalog, but the underlying files are not deleted:
