
=== Deploy a volume

>>> [CLI] bundle deploy
Uploading bundle files to /Workspace/Users/[USERNAME]/.bundle/test-bundle-[UNIQUE_NAME]/default/files...
Created volumes.volume1
Files: 4 uploaded, 0 deleted
Resources: 1 created, 0 changed, 0 deleted, 0 unchanged

=== Out of band, rename the volume away, and create another one under its name

>>> [CLI] volumes update main.test-schema-[UNIQUE_NAME].myvolume --new-name myvolume-moved
{
  "full_name": "main.test-schema-[UNIQUE_NAME].myvolume-moved",
  "volume_id": "[VOLUME_ID]"
}

=== The other volume has another volume_id, so the plan does not take it for the bundle's: it plans a create

>>> [CLI] bundle plan
Warning: resources.volumes.volume1: id="main.test-schema-[UNIQUE_NAME].myvolume" holds another object: its volume_id is "[FOREIGN_VOLUME_ID]", not "[VOLUME_ID]" as recorded, so this bundle does not take it for its own. If the bundle's was renamed outside the bundle, set its name in the config to the new one. If this object is the bundle's (deleted and created again outside the bundle), run 'bundle deployment unbind' and then 'bundle deployment bind' to manage it again.

create volumes.volume1

Plan: 1 to add, 0 to change, 0 to delete, 0 unchanged

=== Deploy takes the renamed volume for the bundle's, and sends nothing to the other one

>>> [CLI] bundle deploy
Uploading bundle files to /Workspace/Users/[USERNAME]/.bundle/test-bundle-[UNIQUE_NAME]/default/files...
Files: 3 uploaded, 0 deleted
Resources: 0 created, 0 changed, 0 deleted, 1 unchanged

>>> print_requests.py //unity-catalog

>>> [CLI] volumes read main.test-schema-[UNIQUE_NAME].myvolume-moved
{
  "full_name": "main.test-schema-[UNIQUE_NAME].myvolume-moved",
  "volume_id": "[VOLUME_ID]"
}

>>> [CLI] volumes read main.test-schema-[UNIQUE_NAME].myvolume
{
  "full_name": "main.test-schema-[UNIQUE_NAME].myvolume",
  "volume_id": "[FOREIGN_VOLUME_ID]"
}

=== Destroy deletes the bundle's volume at its new name, not the other one

>>> [CLI] bundle destroy --auto-approve
The following resources will be deleted:
  delete resources.volumes.volume1

This action will result in the deletion of the following volumes.
For managed volumes, the files stored in the volume are also deleted from your
cloud tenant within 30 days. For external volumes, the metadata about the volume
is removed from the catalog, but the underlying files are not deleted:
  delete resources.volumes.volume1

All files and directories at the following location will be deleted: /Workspace/Users/[USERNAME]/.bundle/test-bundle-[UNIQUE_NAME]/default

Destroy: 1 deleted

>>> print_requests.py //unity-catalog
{
  "method": "DELETE",
  "path": "/api/2.1/unity-catalog/volumes/main.test-schema-[UNIQUE_NAME].myvolume-moved"
