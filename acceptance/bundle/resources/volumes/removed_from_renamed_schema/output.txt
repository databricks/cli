
=== Deploy a schema with a volume in it, and rename the schema out of band

>>> [CLI] bundle deploy
Uploading bundle files to /Workspace/Users/[USERNAME]/.bundle/test-bundle-[UNIQUE_NAME]/default/files...
Created schemas.schema1
Created volumes.volume1
Files: 3 uploaded, 0 deleted
Resources: 2 created, 0 changed, 0 deleted, 0 unchanged

>>> [CLI] schemas update main.test-schema-[UNIQUE_NAME] --new-name test-schema-renamed-[UNIQUE_NAME]
{
  "full_name": "main.test-schema-renamed-[UNIQUE_NAME]",
  "schema_id": "[SCHEMA_ID]"
}

=== Follow the rename in the config and remove the volume from it: the plan keeps the schema and finds the volume under its new name

>>> [CLI] bundle plan
delete volumes.volume1

Plan: 0 to add, 0 to change, 1 to delete, 1 unchanged

=== Deploy deletes the volume at its new name

>>> [CLI] bundle deploy --auto-approve
Uploading bundle files to /Workspace/Users/[USERNAME]/.bundle/test-bundle-[UNIQUE_NAME]/default/files...

This action will result in the deletion or recreation of the following volumes.
For managed volumes, the files stored in the volume are also deleted from your
cloud tenant within 30 days. For external volumes, the metadata about the volume
is removed from the catalog, but the underlying files are not deleted:
  delete resources.volumes.volume1
Deleted volumes.volume1
Files: 2 uploaded, 0 deleted
Resources: 0 created, 0 changed, 1 deleted, 1 unchanged

>>> print_requests.py //unity-catalog
{
  "method": "DELETE",
  "path": "/api/2.1/unity-catalog/volumes/main.test-schema-renamed-[UNIQUE_NAME].myvolume"
}

>>> musterr [CLI] volumes read main.test-schema-renamed-[UNIQUE_NAME].myvolume
Error: Volume 'main.test-schema-renamed-[UNIQUE_NAME].myvolume' does not exist.

>>> [CLI] bundle destroy --auto-approve
