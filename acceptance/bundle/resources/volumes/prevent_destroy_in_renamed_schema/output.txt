
=== Deploy a schema with a volume in it that must not be destroyed

>>> [CLI] bundle deploy
Uploading bundle files to /Workspace/Users/[USERNAME]/.bundle/test-bundle-[UNIQUE_NAME]/default/files...
Created schemas.schema1
Created volumes.volume1
Files: 2 uploaded, 0 deleted
Resources: 2 created, 0 changed, 0 deleted, 0 unchanged

=== Rename the schema out of band. UC moves the volume with it

>>> [CLI] schemas update main.test-schema-[UNIQUE_NAME] --new-name test-schema-renamed-[UNIQUE_NAME]
{
  "full_name": "main.test-schema-renamed-[UNIQUE_NAME]"
}

=== Destroy finds the volume in the renamed schema, so prevent_destroy still stops it

>>> musterr [CLI] bundle destroy --auto-approve
Error: resources.volumes.volume1 has lifecycle.prevent_destroy set, but the plan calls for this resource to be recreated or destroyed. To avoid this error, disable lifecycle.prevent_destroy for resources.volumes.volume1


>>> print_requests.py //unity-catalog

>>> [CLI] volumes read main.test-schema-renamed-[UNIQUE_NAME].myvolume
{
  "full_name": "main.test-schema-renamed-[UNIQUE_NAME].myvolume"
}

=== With the volume renamed out of band too, it is not found, but destroy still lists it, so prevent_destroy still stops it

>>> [CLI] volumes update main.test-schema-renamed-[UNIQUE_NAME].myvolume --new-name myvolume2
{
  "full_name": "main.test-schema-renamed-[UNIQUE_NAME].myvolume2"
}

>>> musterr [CLI] bundle destroy --auto-approve
Error: resources.volumes.volume1 has lifecycle.prevent_destroy set, but the plan calls for this resource to be recreated or destroyed. To avoid this error, disable lifecycle.prevent_destroy for resources.volumes.volume1


>>> print_requests.py //unity-catalog

>>> [CLI] volumes read main.test-schema-renamed-[UNIQUE_NAME].myvolume2
{
  "full_name": "main.test-schema-renamed-[UNIQUE_NAME].myvolume2"
}
