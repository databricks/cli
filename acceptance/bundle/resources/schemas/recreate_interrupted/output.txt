=== Rename the schema and change its storage_root, which recreates it. The CLI is killed on the volume's recreate, after the schema's

>>> update_file.py databricks.yml test-schema- test-schema-renamed-

>>> update_file.py databricks.yml s3://mybucket/a s3://mybucket/b

>>> errcode [CLI] bundle deploy -q --auto-approve
Uploading bundle files to /Workspace/Users/[USERNAME]/.bundle/test-bundle-[UNIQUE_NAME]/default/files...

This action will result in the deletion or recreation of the following UC schemas. Any underlying data may be lost:
  recreate resources.schemas.schema1

This action will result in the deletion or recreation of the following volumes.
For managed volumes, the files stored in the volume are also deleted from your
cloud tenant within 30 days. For external volumes, the metadata about the volume
is removed from the catalog, but the underlying files are not deleted:
  recreate resources.volumes.volume1
[PROCESS_KILLED]

Exit code: [KILLED]

=== The next deploy creates a new volume

>>> [CLI] bundle deploy --force-lock
Uploading bundle files to /Workspace/Users/[USERNAME]/.bundle/test-bundle-[UNIQUE_NAME]/default/files...
Created volumes.volume1
Files: 0 uploaded, 0 deleted
Resources: 1 created, 0 changed, 0 deleted, 1 unchanged

>>> print_requests.py //unity-catalog
{
  "method": "POST",
  "path": "/api/2.1/unity-catalog/volumes",
  "body": {
    "catalog_name": "main",
    "name": "myvolume",
    "schema_name": "test-schema-renamed-[UNIQUE_NAME]",
