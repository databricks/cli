=== The schedule state is write-once, so declaring one on a streaming member that had none
=== plans as a recreate rather than an in-place update
>>> update_file.py databricks.yml           streaming_mode:           pipeline_schedule_state: PAUSED
          streaming_mode:

>>> [CLI] bundle plan -o json

>>> jq .plan | with_entries(select(.key | startswith("resources.materialization_sets"))) | map_values(.action) out.plan.json
{
  "resources.materialization_sets.set1": "recreate"
}

=== Repointing a member's online destination is a recreate: the server cannot move a
=== materialization in place, so the whole set is rebuilt at the new location
>>> [CLI] bundle plan -o json

>>> set_action
recreate

=== Removing one feature's streaming member is an update the endpoint accepts. With no offline
=== member to cascade from, each online member is its own cascade group, so the other feature's
=== member is untouched and the set is left non-empty.
>>> [CLI] bundle plan -o json

>>> set_action
update
