=== The failed resource is listed without a resource_id or state, so a later deploy plans to create it rather than treating it as already deployed
>>> [CLI] api get /api/2.0/bundle/deployments/[NUMID]/resources
{
  "resources": [
    {
      "last_action_type": "OPERATION_ACTION_TYPE_CREATE",
      "last_version_id": "1",

      "resource_type": ""
    }
  ]
}

=== Redeploying from DMS state alone still creates the failed resource: it was never applied, so it must not be skipped as unchanged
>>> [CLI] bundle plan
create jobs.doomed

Plan: 1 to add, 0 to change, 0 to delete, 0 unchanged
