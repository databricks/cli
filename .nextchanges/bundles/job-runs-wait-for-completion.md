direct: the experimental `job_runs` resource now waits for the triggered run to finish, so other resources can reference the run's outcome (e.g. `${resources.job_runs.nightly.state.result_state}`). The deploy reports the run page URL while it waits, and a run that does not succeed fails the deploy, naming the failed task and the message it reported. A failed run stays recorded, so the next deploy does not run the job again.
