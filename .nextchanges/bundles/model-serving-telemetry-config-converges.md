Fixed `telemetry_config` on model serving endpoints never converging on the direct engine: the backend provisions a telemetry profile for the endpoint and returns its `telemetry_profile_id` on GET, which was reported as drift, so every `bundle plan` after a deploy showed the endpoint as a perpetual update. Changes to `telemetry_config` are now applied through the serving endpoints telemetry configuration API instead of being dropped, and telemetry the bundle does not declare is left in place instead of being deleted on the next deploy. Setting `telemetry_config` on an endpoint that serves nothing is now an error from `bundle validate`: the backend types such an endpoint as `NO_CONFIG` and rejects telemetry configuration on it, so the field used to be accepted at deploy time and then ignored ([#6106](https://github.com/databricks/cli/pull/6106)).
