direct: Fixed `telemetry_config` on model serving endpoints never converging, and edits to it being planned and then silently dropped. The backend creates a telemetry profile from `table_names` and returns only the resulting `telemetry_profile_id` on GET, so every `bundle plan` after a deploy reported a perpetual update. Telemetry the bundle does not declare is now left in place instead of being deleted on the next deploy, and a deploy that changes both `config` and `telemetry_config` waits for the endpoint to settle instead of failing on the telemetry call ([#6106](https://github.com/databricks/cli/pull/6106)).
