* `air list` and `air get` now read the AI Runtime task wherever it sits in a multi-task job (for example after a notebook prep task) instead of the first task. A job with several AI Runtime tasks lists one row per task, named in the table's Run ID column (so `run_id` is no longer unique in `air list -o json`, and `--limit` still counts runs); each such row and `air get --task-key` report that task's own status and timing, and `air get` shows the selected task's environment. `air get` gains `--task-key`, and both commands report `task_key` in JSON output (`null` for a run without an AI Runtime task). Runs with a single task report as before. ([#7632](https://github.com/databricks/cli/pull/7632))
