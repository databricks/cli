* `air list` and `air get` now read the AI Runtime task wherever it sits in a multi-task job (for example after a notebook prep task) instead of the first task; a job with several AI Runtime tasks lists one row per task (so `run_id` is no longer unique in `air list -o json`, and `--limit` still counts runs), each row and `air get --task-key` report that task's own status, `air get` gains `--task-key`, and both commands report `task_key` in JSON output.
