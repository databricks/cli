* `air list` and `air get` now read the AI Runtime task wherever it sits in a multi-task job (for example after a notebook prep task) instead of the first task. A job with several AI Runtime tasks lists one row per task, named in the table's Run ID column (so `run_id` is no longer unique in `air list -o json`, and `--limit` still counts runs); each such row and `air get --task-key` report that task's own status and timing (except that a task whose latest attempt failed shows the run's RUNNING, with no failure reason, while another task of the run is still active, since it may yet be retried), and `air get` shows the selected task's environment. `air get` gains `--task-key`, and both commands report `task_key` in JSON output (`null` for a run without an AI Runtime task). Runs with a single task report as before, except that `air list --all-status` now orders runs by submission time, as the run index pages them, rather than by their latest attempt's start.
