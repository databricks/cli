* `databricks aitools install` now reports a coding agent as failed, with a step to recover, when it cannot write the skill files into that agent's skills directory (for example one left owned by root by an earlier run with sudo). It used to report the agent as installed and exit with code 0; it now exits with code 1 when that agent was named with `--agents` or no other agent was set up. `databricks apps init` names such an agent with the same kind of step, and the automatic install retries when no agent got the skills. ([#7962](https://github.com/databricks/cli/pull/7962))
