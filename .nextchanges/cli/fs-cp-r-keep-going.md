* `databricks fs cp -r` keeps going when a file fails. A file that fails with a temporary error (HTTP 408, 429, 5xx, or a network error) is retried once after the rest of the copy, and other failed files are reported while the copy continues. The copy stops early on an authentication or permission error, or on a directory it cannot list or create. A summary goes to stderr, and the command exits with code 1 if any file was not copied. ([#7712](https://github.com/databricks/cli/pull/7712))
